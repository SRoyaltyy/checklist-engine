# 2026-11-04 — why v53 never loaded

The composer stall fix (5.3 logic) has been in agent/BRIDGE.user.js since it was written.
It never executed once. Chain of causes, all real:

1. The loader does not read the bridge's @version. It reads agent/BRIDGE_VERSION.json and
   takes its sha field as an opaque swap token. So a correct body under an unchanged token
   is invisible.
2. That token was set to 5.3.0 when 5.3 was written. The 5.3 body then failed the 90s
   liveness check once, was rolled back to the cached 5.1 body, and 5.3.0 was pushed onto
   the permanent bad list. refresh() now short-circuits on the token comparison and init
   falls back to cache. Badge reads v51 forever.
3. The bridge file's own @version still says 5.1 while carrying 5.3 logic, which is what
   made this look like a rollback of a version that never existed.

Also established: code read through chat loses every angle bracket because the renderer eats
tag-shaped spans. A status test like greater-or-equal 200 then less-than 300 arrives mangled.
base64 via the contents API survives intact and is the only safe way to read code. Four
wrong theories came from misreading mangled operators.

Writes do persist. Three PUTs landed while the queue was saturated: agent/SEC_403_STATUS.md,
agent/WAKE_PROMPT.md, agent/LOADER.user.js 1.5 to 1.6. A stale raw read of
BRIDGE_VERSION.json showed 5.3.0 and briefly looked like a lost write; raw caches for about
five minutes. Do not treat a raw read as a post-write confirmation.

1.6 changes: swap identity is a content hash, not the token file. Bad list keys on hash.
One retry before blacklisting. Settle window 120s. Cache-buster on every fetch. Bad entries
from the token era are inert.

## Later findings

A PUT body is cut at the first END token anywhere inside it, newline optional. The writer
takes that as the close. The first WAKE_PROMPT.md write was truncated to 256 bytes this way
and a loose pass then created a junk file literally named "path". Rule: no END token inside
a body, no line beginning with the PUT marker. The rewrite spells the markers out in prose.

The RUNS directive is fire-and-forget. Its handler calls the Worker runs op and only logs the
status; nothing is delivered into chat. It can never prove anything. Run verdicts must come
from the actions API with per_page, which is JSON and survives delivery intact.
