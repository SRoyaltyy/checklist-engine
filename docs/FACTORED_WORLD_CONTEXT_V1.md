# Native context values on the full approved stock-day universe

This stage adds the existing macro, CBOE and 25-ETF data to the approved stock-day view. It consumes stitch v2 (8,316 of 8,727 original names, 411 explicit exclusions, 12,364,370 query stock-days) and the previously released ETF native blocks. It does not restart the active price-answer matrix 40621517496.

The legacy `world_fred.columns` reduced values to float32. That loses source precision: for example, 1.0000000001 becomes 1, and 1e39 overflows. The new context version retains float64 for latest-known values, first releases and ages. The original archived ALFRED values remain the source; no new provider request is needed. CBOE values, native changes and term ratios also remain float64. Old context v1 assets stay immutable; corrected blocks publish under **shared-context-v2**. Future-cut checks rebuild every native context at both registered cutoffs and require exact dataframe equality, including dtype.

All numeric native columns and all 22 timeframes remain stored. Shared values are stored once in their complete native Parquet blocks. `world_context_store.context_row_view` reconstructs the corresponding stock-session row through exact availability joins. It does not recompute indicators, reduce precision, remove constant/correlated features or substitute a current sector label. The caller must supply actual authenticated stock-session dates; this component does not create stock rows merely from a ticker string. Execution-only D-open fields and nonnumeric narrative fields are rejected from factor features.

The point-in-time rule is `source_candle_end < available_from <= D`; ALFRED compilation additionally requires `vintage_date < native availability`. The sampled age columns refer to the native sample date. A context row with missing values stays missing in the stock view; an as-of join cannot skip it and expose an older known value instead. Date keys normalize to nanoseconds, including when pandas creates microsecond input dates. Literal ticker `NA` remains a literal identity.

The producer binds every source/report/native-file/calendar hash and checks all registered timeframes and dimensions. Coverage uses the exact approved count of stock rows on each date. For example, if valid values occur on dates weighted 100 and 9, with a missing date weighted 1, coverage is 109/110, not 2/3. It reports per-column/per-timeframe stock-day count, non-null percentage, first/last date, dtype and source binding; a zero-observation row cannot become WIRED. This requires no duplicate 8,316-stock copies of the same shared values.

The release contains the executable factor manifest, complete source column registry and `WORLD_SHARED_STOCK_DAY_COVERAGE.csv`. It is an addition to the world store, not a complete-world acceptance claim. Stock-relative features, historical sector/industry assignment and peers remain separate work. Other event/fundamental/news blocks, complete v3 questions, comprehensive leak proof, historical tradeability/size eligibility, numeric retention and the full dependency budget remain required. No 1.43/1.44/1.45 or other checkbox is pre-claimed from source attachment alone.
